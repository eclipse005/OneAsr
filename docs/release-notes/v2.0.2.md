# OneAsr 2.0.2 — Your transcript is the subtitle

> **Preview build** — continues the Electron line after 2.0.1 and is marked as a pre-release on GitHub. The stable GPUI release remains available on the releases page.

This release fixes the one thing transcript matching must never get wrong: the subtitle text. If your transcript line reads `月亮 代表 我的 心`, the subtitle now reads exactly that — spaces and all.

## New

- **Beautify moved to the transcript panel**: a `Beautify` button next to `Smart split` applies the finished-subtitle polish to the transcript itself, before aligning. Result and line count are visible in the panel before you start, and the source file is still never written.
- **Transcript panel layout**: `Smart split`, `Beautify` and `Re-read` sit together on the left; `Remove transcript` moved to the bottom-right corner beside Save, away from the everyday actions.
- **Tooltip on the Settings toggle**: `Subtitle polish` now says it applies to transcription only — transcript rows use the panel button.

## Fixed

- **Transcript matching keeps your text exactly**: every subtitle is now the transcript line it comes from, character for character — spaces inside a line, double spaces, full-width spaces, full-width punctuation. Before, the text was rebuilt from the aligned tokens, which dropped the spacing you typed between Chinese characters (and could add a space after a `,` you never wrote).
- **No rewriting after alignment**: transcript runs never polish the subtitle text. The `Beautify` setting applies to transcription only; the CLI's `--beautify` on an align run now says it is ignored instead of quietly doing nothing.
- **Karaoke ASS matches the SRT**: in transcript runs the ASS carries the same text, with your spaces written as hard spaces, so the two files a task produces never disagree.
- **Smart split only moves line breaks**: splitting a long line now cuts the original text instead of re-joining its words, so spacing inside the line survives the split.

## macOS Install

The package is unsigned (no Apple Developer account), so the first install needs the system's quarantine mark cleared once; afterwards there are no prompts. The disk image includes 安装说明.txt and 安装 OneAsr.command:

1. Run it in Terminal — the method that works on every macOS version:

```bash
bash "/Volumes/OneAsr 2.0.2/安装 OneAsr.command"
```

2. If you prefer Finder, right-click 安装 OneAsr.command → choose "Open" → click "Open" again in the dialog.

(In Terminal, type `bash` plus a space, then drag the script icon into the Terminal window — the path fills in automatically.)

# OneAsr 2.0.2 — 你的文稿就是字幕

> **预览版** —— 接续 2.0.1 的 Electron 线，在 GitHub 上标记为预发布（pre-release）。稳定的 GPUI 正式版仍可在 Releases 页面下载。

这一版修的是文稿匹配最不该错的那件事：字幕的文字。文稿里写的是 `月亮 代表 我的 心`，字幕里就是一模一样的这一行，空格原样保留。

## 新增

- **美化字幕搬进文稿面板**：`智能断句` 旁边多了一颗 `美化字幕`，把成稿美化作用在文稿本身、在打轴之前。结果与行数在面板里就能看到，源文件仍然一个字都不写。
- **文稿面板重排**：`智能断句`、`美化字幕`、`重新读取` 三颗并排；`移除文稿` 挪到右下角与保存同一排，不再和日常动作混在一起。
- **设置里的开关加了说明**：`成稿字幕美化` 现在写明只影响转写，文稿任务用面板上那颗按钮。

## 修复

- **文稿匹配原样保留你的文字**：每条字幕就是它来源的那一行文稿，逐字不变——行内空格、连续空格、全角空格、全角标点都原样。之前文字是从对齐结果重拼的，汉字之间的字距会消失（还会在逗号后面凭空多出一个你并没写的空格）。
- **对齐之后不再改字**：文稿任务的美化只发生在打轴之前；设置里的「成稿字幕美化」对文稿任务不生效。CLI 在 `align` 上给 `--beautify` 会明确提示已忽略，不再静默失效。
- **卡拉OK ASS 与 SRT 对得上**：文稿任务里 ASS 用的是同一份文字，你的空格写成硬空格，同一次产出的两个文件不会再互相打架。
- **智能断句只动换行**：切长行时改为按原文切片，不再重拼词，所以行内的空格与字距能活过切分。
