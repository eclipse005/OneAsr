# OneAsr 1.4.1 — transcript subtitles no longer trail the voice

## Fixed

- **Transcript matching now times each cue by its first and last character, not by the whole aligner token**: the aligner glues punctuation onto the preceding character (`道：“` is one token), so a line of your script often ends in the middle of a token. The old code handed such a token to the earlier line and started the next line at the token *after* it, so every line pushed the timing a little further behind the audio. On a 15-minute script that came to 2 seconds by the end. Cues are now exact.
- **A line that starts with punctuation no longer appears early**: an opening quote has no duration of its own, so the cue now starts when the first character that is actually spoken begins, instead of jumping back to the previous line's last character.

## macOS Install

The package is unsigned (no Apple Developer account), so the first install needs the system's quarantine mark cleared once; afterwards there are no prompts. The disk image includes 安装说明.txt and 安装 OneAsr.command:

1. Run it in Terminal — the method that works on every macOS version:

```bash

```

2. Or right-click 安装 OneAsr.command → "Open" → "Open" again in the dialog.

# OneAsr 1.4.1 — 文稿字幕不再落后于声音

## 修复

- **文稿匹配按首末字取时间，不再按整个对齐单元取**：对齐器会把标点粘在前一个字上（`道：“` 是一个单元），而文稿的一行常常正好切在这种单元中间。旧实现把这种单元整个判给前一行、下一行从它**后面**那个单元起步，于是一行推一点、越往后越偏；15 分钟的文稿到末尾已经偏了 2 秒。现在每条字幕的时间都精确。
- **以标点开头的一行不再提前出现**：开引号本身没有时长，字幕改为从**真正开口的那个字**开始，不再跳回上一行末字被说出来的时刻。
