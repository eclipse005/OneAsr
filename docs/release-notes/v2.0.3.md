# OneAsr 2.0.3 — transcript subtitles no longer trail the voice

> **Preview build** — continues the Electron line after 2.0.2 and is marked as a pre-release on GitHub. The stable GPUI release remains available on the releases page.

This release fixes the timing of transcript-matched subtitles: each cue now appears when its first character is actually spoken, instead of progressively later.

## Fixed

- **Transcript subtitles stay in sync**: the aligner glues punctuation onto the preceding character (`道：“` is one unit), so a line of your transcript often ends in the middle of a unit. The old code handed that unit to the earlier line and started the next line at the unit *after* it, so every line pushed the timing a little further behind the audio — 2 seconds by the end of a 15-minute script, and up to 14 seconds on a finely split transcript. Cues are now timed by their first and last character.
- **A line that starts with punctuation no longer appears early**: an opening quote has no duration of its own, so the cue now starts when the first character that is actually spoken begins, instead of jumping back to the previous line's last character.

# OneAsr 2.0.3 — 文稿字幕不再落后于声音

> **预览版** —— 接在 2.0.2 之后的 Electron 线，在 GitHub 上标记为 pre-release。稳定的 GPUI 版本仍在发布页上下载。

这一版修复文稿匹配的时间：每条字幕在它的**首字真正被说出来**时出现，而不是越往后越晚。

## 修复

- **文稿字幕与声音保持同步**：对齐器会把标点粘在前一个字上（`道：“` 是一个单元），而文稿的一行常常正好切在这种单元中间。旧实现把这个单元整个判给前一行、下一行从它**后面**那个单元起步，于是一行推一点、越往后越偏——15 分钟的文稿到末尾偏了 2 秒，切得细的文稿能偏到 14 秒。现在按每行的首末字取时间。
- **以标点开头的一行不再提前出现**：开引号本身没有时长，字幕改为从**真正开口的那个字**开始，不再跳回上一行末字被说出来的时刻。
