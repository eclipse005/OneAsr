# 从已合并的改动里学到的

AGENTS.md 的「代码风格」里那些规矩不是凭空来的，每一条底下都有一次具体的
翻车。这里记它们：**规则 → 为什么 → 证据**。

## 怎么用

- **改代码前先读一遍。** AGENTS.md 告诉你该怎么做，这里告诉你为什么、以及
  上一次不做会付出什么代价。
- **记新条目时必须带证据**：哪次提交、哪天、现象是什么。「我觉得这样比较好」
  不算证据，没有证据的条目不要往里写。
- **Seen 记的是被违反的次数**，不是同意的次数。第 3 次被撞上的规则才迁进
  AGENTS.md，迁了之后两边都要读——AGENTS.md 是规矩的正文，这里是它的来历。
  没到 3 次的先留在这里攒着，避免把凭直觉的偏好写成一生的标准。
- **「写测试」「改好了」这类不算验证。** 要写清楚跑了什么、坏了哪条代码
  才变红、什么没试。没试的那部分照实写「未验」，别让假绿变成没人知道。

## 1. 一次修一类，不修一个

**规则**：改 bug 前先 grep 同构的兄弟位置，一次改完。只修报告里那一个，
用户换个场景就会带着同一个 bug 回来。

**为什么**：同构的代码长在一个仓库里，报告只会来自最先撞上的那一个。
只修那一个，等于把同一个错误留在另外 N 个地方，只是暂时没人走到。

**证据**：

- `d6a3fb9`（2026-09-27）——教科书级的反面教材。上一轮把 14 个写死
  Windows 路径的测试改完了，**漏了一处**：`try_from_aligner_dir` 里同样写着
  `r"C:\m\Qwen3-ForcedAligner-0.6B-hf"`，成因一模一样（Linux 上 `file_name()`
  拿不到目录名）。上一轮只按 ASR 找、漏了 aligner，CI 上又红了一轮。
- 正面样板 `6f59205`（2026-09-27）——同一件事一次做完：分隔符问题在
  paths / asr / settings 共 10 处，路径解析 3 类，平台大小写 1 类，另有 2 处
  断言的是本机环境而不是产品不变式。它还在正文里逐条说明了哪些**不用改**以及
  为什么不用改（`r"D:\__no_such_*__"` 任何平台上都不是目录，断言照常成立）。
- 正面样板 `7548d82`（2026-10-06）——「文稿卡片从来没被打开过」，同一个根因
  的三条路（悬停 / 点击 / 选完文件）全断。修法不是补三处，而是收敛到一个入口
  `open_transcript_card`，让「漏不掉」成为结构上的事实。

**Seen**：3×（`d6a3fb9` 漏 aligner；`06858f7`→`5d010c7`→`dbdcc1c`→`d03eade`→
`f592587` 断句区 2026-09-29 至 10-11 连续五次同类修复）

## 2. 静默的空测试，比红测试更坏

**规则**：测试读不到东西时，不要 `early-return`。要么 `#[ignore]` 让它在结果里
老实显示为 ignored，要么用临时目录造出它要读的东西。**读到失败 ≠ 通过。**

**为什么**：一个永远绿、却什么都没断言的测试，比一个红的测试危险得多。
红的测试会被人看见并去修；它只会在报告里留下一行漂亮的 "ok"，让人以为那条
路径验过了。按 AGENTS.md 的话：**别让"假绿"变成"没人知道"**。

**证据**：

- `d6a3fb9`（2026-09-27）——sentence_boundary 的回放测试兜底了一个写死的
  本机 `%TEMP%\vt_asr_mfkge5.json`，读不到就 early-return。提交里写得很直白：
  「它在 CI 上等于一个断言都没跑，却报 "ok" —— 静默空测试比红测试更坏，让人
  以为回放路径验过了」。改法是只认环境变量并标 `#[ignore]`。
- `scripts/test_verify_i18n.py`（2026-10-14）——写门禁自测时当场踩到同一条的
  另一个形状：一条用例断言「源码目录缺失时必须失败」，但它只改了 `GUI_SRC`，
  双语表仍然读不到，于是 `main()` 因**别的**理由返回 1。守卫拆掉后用例照样绿。
  凡是「期望失败」的用例，都要把周围状态摆成正常，只留那一个故障点。

**Seen**：2×（2026-09-27；2026-10-14）

## 3. 单测必须跨平台，且断言的是不变式不是本机状态

**规则**：路径用 `join` 构造，不许写死 `r"D:\…"` 当期望值；断言平台串要大小写
不敏感；不要断言仓库里有没有 `bin/ffmpeg`、`models/` 在不在。

**为什么**：CI 只在 ubuntu 上跑，开发机是 Windows。**在 Windows 上绿的测试
可能从来没被真正验证过**——它比的是分隔符，而被测的规则根本没被执行。

**证据**：

- `6f59205`（2026-09-27）——14 个测试在 ubuntu 上红着、本地 Windows 全绿，
  所以「这些测试一直没被真正验证过」。三类根因：① 分隔符，生产用 `Path::join`
  而期望值写死字面量；② 路径解析，`r"D:\Movies\lecture.mp4"` 在 Linux 上没有
  分隔符、`parent()` 返回空，那条分支根本走不到；③ 大小写，`consts::OS` 是小写
  `linux`，UA 里是 `X11; Linux x86_64`，Windows 恰好因为 UA 里有 `Windows NT`
  而通过，**属于运气**。另有两处断言的是环境而非产品不变式，已拆成吃参数的
  纯函数、用临时目录树测。
- `a95bbc6`（2026-10-07）——ubuntu 的 clippy `field_reassign_with_default`
  只在 CI 上暴露，本地 Windows 全绿。

**Seen**：2×（2026-09-27；2026-10-07）

## 4. 发版才第一次编译的那条路，等于没人验

**规则**：lint 与测试只在 ubuntu 跑是不够的，跨平台编译要在提交时就验。

**为什么**：等发版才第一次编译的平台，中间那段时间等于无人值守——问题在那儿
积累，等发现时已经是一串连坐。

**证据**：

- `f4b4258`（2026-10-07）——macOS 得等到发版打包才第一次编译，v1.2.0 的两颗雷
  （ctc 引用的 Vulkan 类型在 macOS 不存在、libc 0.2.190 删掉 xattr 要用的
  `ENOATTR`）就在那个空档里暴露，发布流水线连红两轮才定位完。改法是矩阵加
  `macos-latest` / `windows-latest` 各跑一个 `cargo check`，把「发版才炸」
  提前到「提交即红」。它同时记下了**为什么不做 clippy、不跑测试**：拦编译失败
  就够，翻倍只会烧 runner。

**Seen**：1×（2026-10-07）——还没到 3 次，但代价是一整个发布流程连红两轮，
先留着。

## 5. 门禁自己也要有测试

**规则**：校验脚本（`scripts/verify-*.py`）改过之后，要么给它补单测，要么用
断骨工具证明它的每条检查都有对应用例守着。

**为什么**：改坏门禁的一条正则，它不会报错，只会**静默地永远放绿**。这种失效
比门禁本身的红危险得多——连「被拦住过」都不是了，而且没有编译错误、没有测试
失败、CI 一路全绿。

**证据**：

- `scripts/verify-i18n.py`（2026-10-14）——注入 10 组违规实测，发现
  `in_lang_arm` 只回「在不在臂里」而不回「是哪个臂」，于是中文写进
  `UiLang::En` 臂会放绿（Zh/En 写反是改 i18n 时最高频的手滑）。
  另一处是英文侧留空 `Str::new("退出码", "")` 只比占位符集合，两侧都空就相等。
  两条都已修。
- 同一个提交里也记下**为什么不查别的**：渲染层的硬编码英文（误报压不住）、
  `Str::new` 两侧同文（仓库里有 4 处合法的语种标签 `语言`/`English`/`语`/`En`，
  写了就是 4 条常驻误报）。想「顺手加强」之前，先读 `verify-i18n.py` 文件头
  那节「为什么不查别的」。

**Seen**：1×（2026-10-14）
